# Protocol reference

Candidate rows use exactly `KIND<TAB>ESCAPED_DISPLAY<TAB>PADDED_BASE64_PAYLOAD`, framed by NUL for fzf input. The closed kind set is local, directory, file, zoxide, drive, and `KindVirtual`. Payloads are nonempty canonical payload base64: decoding then re-encoding must produce the identical padded text. The only virtual payload is the target `drives`, whose canonical payload is `ZHJpdmVz`; it is navigation metadata, not a filesystem path.

The zoxide source boundary accepts at most 4 MiB total output, 1,000,000 rows, and 128 KiB per row. These limits match the protocol's external output and candidate-count bounds while covering legal platform paths, including Windows extended paths. An exact limit is valid; limit plus one is a malformed soft failure, all records are discarded, and the child is cancelled and reaped.

Callbacks have a closed grammar: events are exactly `e:mi`, `e:ma`, `e:es`, `e:fw`, `e:up`, `e:sl`, `e:hm`, `e:en`, or `e:rs`; preview is exactly `p` or the fixed local `p:invalid`; display is exactly `d`; info is exactly `i:cd` or `i:cp`; coordinator-backed loads are `l:<positive decimal generation>:<positive decimal eventID>`, while non-coordinator loads may use `l:<positive decimal generation>`; neither component permits zero, sign, or leading zero. The fixed local `l:empty` is a zero-byte candidate source, and `p:invalid` writes exactly `[Invalid Path]`. Fixed local callbacks accept no query or path arguments and bypass IPC. `FZF_CURRENT_ITEM` carries the selected wire row. The callback parser rejects every other form instead of interpreting shell text.

Event JSON is `opcode`, `key`, `query_base64`, and `current_item_base64`; an event response is `{"effect":{...},"event_id":N}`. Coordinator-backed CD events carry an opaque nonzero `event_id`; CP and other no-coordinator backends use `event_id: 0` and require no finalization. The authenticated POST /v1/event/finalize route accepts exactly `{"event_id":N,"applied":true|false}` for a nonzero ID. `applied` is true only after the callback has rendered the complete action and written all action bytes; false is a hard callback-application failure that closes input, cancels source/work, and is returned by the picker. The protocol retains the idempotent event finalization rule for duplicate event acknowledgements. Load JSON is `generation` plus `event_id`; coordinator loads must use the exact event ID encoded in the load command. The authenticated POST /v1/load/finalize route accepts exactly `{"event_id":N,"applied":true|false}`. Load finalization is true only after all returned candidate bytes have been written; false is the same hard failure. Unknown, stale, replayed, or mismatched load IDs/generations are rejected and release nothing; the display request is `{}` and its response is `{"header":"..."}`; preview JSON is `phase`, `current_item_base64`, and, only where the phase permits it, `renderer`, `duration_us`, `child_starts`, `max_live_children`, and `outcome`. Preview phases are `resolve`, `started`, and `finished`; native finished telemetry has zero child starts/live children. The callback environment accepts only the controlled loopback address and token credentials (`SHELL_PICKER_ADDR` and `SHELL_PICKER_TOKEN`); credentials are strict canonical encodings, not shell arguments. The callback application failure is the hard terminal error for an exact unapplied event or load finalization; callback application failed means the coordinator has terminalized.

`e:rs` is the one-shot transient-view restore event. An invalid list/preview first reloads `l:empty`, selects `p:invalid`, and binds `result-final`; only `result-final`, after invalid rendering completes, arms one `change` callback. The next edit sends `e:rs`. If initial enrichment is still active, this launch-view-only restore deactivates, cancels, and discards that source, then reloads the exact prior generation with its event-qualified load; the restore action resets the normal preview and transient bindings, and the original input closes only after that load is applied. Ordinary mode transitions may carry a same-generation restore generation, but suppress that reload and keep streaming enrichment active.

The listener binds `127.0.0.1:0`. Routes use the literal `RequestURI` /v1/event, /v1/event/finalize, /v1/load, /v1/load/finalize, /v1/display, or /v1/preview; `RawQuery` and `RawPath` must both be empty. Before constant-time token comparison, the server requires exactly one Authorization field with exactly one value in the grammar `Authorization: Bearer <token>`.

The local `info` callback records its privacy-safe start and completion directly through the inherited trace sink; it carries no query, current-item, path, credential, generation, or error-text fields and does not use a session IPC invocation route.

/v1/event/finalize and /v1/load/finalize use the same loopback bearer authentication, method, content-type, body-size, and strict-object validation as the other routes. Event and load IDs are the only authority: the server never accepts a client-supplied effect, generation correlation, or release instruction. An active-stream mode change suppresses its same-generation restore reload while preserving mode/search/prompt/rebind/query effects; an active invalid-view `e:rs` instead discards enrichment and preserves its exact restore load. Event callbacks serialize until exact action/load finalization. Navigation deactivates/discards enrichment before its `l:g:eventID` reload. Applied event finalization waits until the matching /v1/load has cloned and framed the exact bytes; only applied load finalization releases it. Navigation and launch-view restore close/discard the initial input only after their applied matching load; ordinary mode transitions leave the source active; accept/abort finalization never closes input; fzf process exit or explicit picker cleanup owns that close.

Only POST with `Content-Type: application/json` is admitted. JSON event, preview, and error bodies are limited to 64 KiB. Load `application/octet-stream` responses are limited to 64 MiB, and telemetry-empty client responses to 1 KiB. Decoding and draining use limit plus one bytes to distinguish overlimit input; every body is closed, and an overlimit response is not eligible for connection reuse. The server also disables keep-alives and bounds concurrent handlers.

Trace is newline-delimited JSON schema 2. The runtime emits and accepts schema 2 only; legacy schema 1 records are rejected rather than silently reinterpreted. Every record has `schema`, `time`, `session`, `event`, `generation`, `candidate_count`, `renderer`, `child_starts`, `max_live_children`, and `outcome`; optional fields are `path`, `zoxide_policy`, `zoxide_attempts`, `zoxide_starts`, `zoxide_exits`, `zoxide_processes`, `zoxide_live`, `zoxide_max_live`, `actor_queue_wait_us`, `callback_ipc_us`, `local_us`, `zoxide_us`, `zoxide_outcome`, `sidecar_attempt`, `transform_us`, and `load_us`. Events include `callback.info.start`, `callback.event.start`, `callback.display.start`, `callback.preview.start`, and `callback.load.start` with `outcome=started`, followed by base callback completion events with privacy-safe success or `error` outcomes. Other events are `session.start`, `generation.start`, `generation.publish`, `generation.discard`, `zoxide.enrichment`, `fzf.start`, `fzf.exit`, `callback.info`, `callback.event`, `callback.display`, `callback.preview`, `callback.load`, `preview.dispatch`, `preview.finished`, `preview.cancel`, `preview.exit`, `session.close`, `sidecar.get`, `sidecar.post`, and `sidecar.stop`. Sidecar diagnostics contain only operation category, bounded attempt counter, duration, and closed stop reason; they never contain URLs, bodies, credentials, or picker state. The default callback path may emit callback starts and completions; the enabled static-header sidecar path deliberately emits no `callback.info` or `callback.display`, while preview callback records remain invocation traces. Session and path values are truncated SHA-256 redactions; paths, credentials, and error text are not emitted. Trace is diagnostic observation, not a performance guarantee, authorization record, or unredacted audit log.

The machine table is the validator contract. `@renderers`, `@zoxide_policies`, and `@zoxide_outcomes` are the exact accepted vocabularies. Every preview event requires a renderer, while every non-preview event requires an empty renderer. A generation is an unsigned 64-bit value and may be nonzero only for generation start/publish/discard, `zoxide.enrichment`, and callback load start/completion; `zoxide.enrichment` always requires a nonzero generation. Candidate count is 0..1,000,000 and may be nonzero only for generation publish and a `published` zoxide enrichment; path applies only to generation publish. Every recorded `time` is required RFC3339Nano UTC. A caller may omit the input timestamp to use the current time, or supply one inclusively bounded from 24 hours before validation through one second after it.

All six input durations are bounded from zero through 24 hours inclusive and are emitted as microseconds from 0 through 86,400,000,000. Generation timings apply only to publish/discard, callback IPC applies to callback event and callback display, load timing only to callback load, and sidecar local timing applies only to sidecar diagnostics. Sidecar operation records require an attempt from 1 through 1,000,000; sidecar stop records never carry an attempt. The `zoxide_*` bundle means policy plus outcome and may include zoxide counters/duration; it occurs only on generation publish/discard or `zoxide.enrichment`. Zoxide counters are nonnegative; attempts are at most 1,000,000 and bound starts; exits and processes equal starts; live is zero; and `zoxide_max_live` is 0..starts. The runtime coordinator guarantees at most one zoxide source process for a picker session, with balanced starts/processes counts within the attempts bound. `pending` is reserved for the initial CD local generation publication and must have zero terminal counters and duration; schema 2 never permits `pending` on `zoxide.enrichment`. A zoxide enrichment requires a terminal source outcome (never `pending` or `not-run`), exactly one lifecycle outcome of `published`, `discarded`, or `failed`, and never carries a path. Child counters are always zero except on preview.finished and preview.exit; there child starts are 0..3, max live is 0..1 and never exceeds starts, and native remains 0/0.

The initial CD local `generation.publish` is the normal terminal for its existing `generation.start`, but it is only a local snapshot and carries zoxide policy plus `pending`. The one asynchronous source later emits the standalone `zoxide.enrichment` terminal: `published` names the `Actor.Enrich` generation and total merged snapshot, while `discarded` and `failed` always name the immutable initial generation captured by `Activate`, with zero candidates. Navigation and stale/current-base changes remain coordinator mechanics and never change the nonpublished trace identity. The enrichment event is not a generation start/publish pair. CP is local-only and emits no enrichment event.
