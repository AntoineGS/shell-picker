# Preview pipeline

`KindVirtual` is not a filesystem path and is rejected before stat or tool work. Filesystem candidates are classified from metadata/prefix, then use category tool precedence: eza for directories, glow then bat for markdown, bat for text, kitten then chafa for images, archive tools for archives, and native renderers when tools are absent or produce no useful output.

Default limits are a 10-second deadline, 4 MiB output/internal/archive-decompression budget, 100 archive entries, and 64 MiB maximum accepted/cached artifacts. Cache cleanup is best-effort polling, not a hard transient disk cap. Tool paths are absolute and arguments prevent option injection. Unix inherited-group cancellation intentionally terminates the callback without fallback/final telemetry; Windows uses nested containment.

There is at most one simultaneously live converter/renderer and at most three sequential starts are allowed for converter plus kitten plus chafa. The native fallback starts none. Cache keys are SHA-256, and root, component, entry, temporary, publication, timestamp, and prune operations are anchored to opened directory handles. Validated race winners are used. Renderer bytes are intentionally not a parity promise.

On Unix, cache-root components use `openat`/`mkdirat` with no-follow directory opens; entries and exclusive temporary files are then created or reopened relative to those handles. Atomic no-replace publication uses `linkat`, followed by validation across the expected one-to-two-to-one link transition. Timestamp refresh uses the already opened file, while `renameat`/`unlinkat`-style quarantine and pruning operate relative to the reopened root. Every accepted file is bounded, regular, and checked for stable device/inode identity and expected link count before use or removal.

On Windows, component, entry, and temporary opens use NT handle-relative `NtCreateFile` with a root handle, do-not-reparse object attributes, and open-reparse-point semantics; directories or files carrying a reparse attribute are rejected. Atomic no-replace publication is handle-relative `NtSetInformationFile` publication with `FileRenameInformation` and the opened cache root, and pruning uses the same rename primitive plus handle disposition. Accepted files retain volume/file-index identity and expected link count, regular non-reparse type, and bounded size. Cache hits receive handle-based timestamp refresh through `SetFileTime`; private converter stages additionally validate owner-only ACLs and stable marker, directory, and artifact handles.
